工业报警管理系统设计手册

========================================
第一部分：报警管理标准
========================================

IEC 62682 / ISA-18.2 报警管理生命周期：
  1. 报警理念(Philosophy): 定义报警目标和原则
  2. 报警识别(Identification): 确定需要报警的工况
  3. 报警合理化(Rationalization): 评审每个报警的必要性
  4. 报警设计(Design): 设定限值、优先级、延时
  5. 报警实施(Implementation): PLC/DCS编程
  6. 运行维护(O&M): 监控报警性能
  7. 持续改进(MOC): 修改优化

报警KPI指标：
  报警率: <6个/小时/操作员 (ISA-18.2建议)
  过载率: >10个/10min = 报警洪泛
  陈腐报警: 持续>24h未处理的报警占比 < 5%
  确认时间: P1报警平均确认时间 < 5min

========================================
第二部分：报警分级
========================================

四级优先级（ISA-18.2）：
  Priority 1 - 紧急(Critical):
    后果: 安全或环境事故
    响应: 立即，<1min
    示例: 高高液位(溢出)、超压(爆炸)、有毒气体泄漏

  Priority 2 - 高(High):
    后果: 设备损坏或生产中断
    响应: <5min
    示例: 电机过载、温度超限、压力高

  Priority 3 - 中(Medium):
    后果: 产品质量下降
    响应: <30min
    示例: 参数偏差、效率降低、轻微泄漏

  Priority 4 - 低(Low):
    后果: 维护需求提示
    响应: <8h
    示例: 过滤器寿命、润滑到期、运行时间超限

========================================
第三部分：PLC 报警编程模式
========================================

报警数据结构（SCL）：
  TYPE AlarmRecord:
    STRUCT
      ID : DInt;           // 报警编号
      Timestamp : DTL;     // 触发时间
      Priority : Int;      // 优先级 1-4
      State : Int;         // 0=正常 1=激活 2=已确认 3=已处理
      Value : Real;        // 触发时的过程值
      Limit : Real;        // 报警限值
      Description : String[80];
    END_STRUCT
  END_TYPE

报警状态机：
  NORMAL → [触发条件满足+延时] → ACTIVE
  ACTIVE → [操作员确认] → ACKNOWLEDGED
  ACKNOWLEDGED → [触发条件消失] → NORMAL
  ACTIVE → [触发条件消失] → UNACK_RETURN → [确认] → NORMAL

报警抑制逻辑：
  1. 设备未运行时: bRunning = FALSE → 抑制该设备所有报警
  2. 消抖延时: 模拟量报警带 TON 延时(3~30s)
  3. 一级联锁: 上级故障激活 → 抑制下级报警
  4. 搁置(Shelve): 检修期间临时屏蔽(需记录+自动恢复)

========================================
第四部分：模拟量报警模型
========================================

四限报警模型：
  HH(High-High): 极高报警 → 联锁停机
  H (High): 高报警 → 操作员处理
  L (Low): 低报警 → 操作员处理
  LL(Low-Low): 极低报警 → 联锁停机

死区设计（防止抖动）：
  上升报警: 触发 = PV > Limit, 恢复 = PV < Limit - Deadband
  下降报警: 触发 = PV < Limit, 恢复 = PV > Limit + Deadband
  死区 = 量程的 1~3% (经验值)

变化率报警：
  |dPV/dt| > RateLimit → 报警
  用途: 检测传感器异常、管道泄漏、突发工况
  计算: (PV_current - PV_previous) / Δt

========================================
第五部分：报警记录与分析
========================================

记录内容（每条报警）：
  时间戳 | 报警ID | 描述 | 优先级 | 状态变化 | 过程值 | 限值 | 操作员 | 动作

S7-1200/1500 报警实现：
  - ALARM_S/ALARM_8P 指令(S7经典)
  - Program Alarm (TIA V14+，推荐)
  - HMI报警类通知: ProDiag
  - 长期记录: 通过OPC UA/S7通信上传到历史数据库

报警分析方法：
  1. Top 10 频繁报警: 找出最频繁的10个报警进行优化
  2. 洪泛分析: 10min内>10个报警的事件
  3. 陈腐报警清理: 24h内未恢复的报警需评审
  4. 关联分析: 哪些报警总是同时出现(可能有因果关系)
