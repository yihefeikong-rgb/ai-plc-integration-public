TIA Portal V18 与 IEC 61131-3 编程标准参考手册

========================================
第一部分：TIA Portal V18 项目管理
========================================

创建新项目：
- Portal 视图：启动页面 → "创建新项目" → 输入名称/路径/作者 → 创建
- 项目视图：菜单栏"项目" → "新建" → 填写信息 → 创建

项目管理要点：
- 支持项目分组存储在项目服务器上
- 支持项目访问保护和用户权限配置
- 支持全局库跨项目共享和版本管理
- 向上兼容：可用更高版本 TIA Portal 打开
- V18 支持 Multiuser Engineering（多用户工程）

========================================
第二部分：硬件组态
========================================

手动组态步骤：
1. 项目树 → "添加新设备"
2. 选择控制器类别（S7-1200/S7-1500）和 CPU 型号
3. 选择固件版本，设置设备名称
4. 在设备视图配置扩展模块：
   - 通信模块 (CM)：CPU 左侧
   - 信号模块 (SM)：CPU 右侧
   - 信号板/通信板：CPU 本体上（最多 1 个）

S7-1200 模块连接规则：
- 信号板：CPU 本体，最多 1 个
- I/O 信号模块：CPU 右侧，1214C/1215C/1217C 最多 8 个，1212C 最多 2 个，1211C 不支持
- 通信模块：CPU 左侧，最多 3 个

网络组态：
- 在"网络视图"中组态 PROFINET/PROFIBUS 网络
- 创建 S7 连接、HMI 连接、TCP/UDP/ISO-on-TCP 连接

========================================
第三部分：程序块类型
========================================

OB（组织块）：系统事件驱动调用，OB1 为主循环
FB（功能块）：有背景数据块（实例 DB），可保存状态
FC（函数）：无背景数据块，纯逻辑运算
DB（数据块）：存储数据，分全局 DB 和实例 DB

常用 OB 类型：
- OB1：主循环，周期性执行
- OB10-OB17：日期时间中断
- OB20-OB23：延时中断
- OB30-OB38：循环中断（固定间隔，如 OB30 默认 5ms）
- OB40-OB47：硬件中断
- OB80-OB87：错误中断
- OB100：启动中断（STOP→RUN 时执行一次）
- OB121-OB122：编程/IO 错误

创建程序块步骤：
1. 项目树 → PLC 设备 → "程序块"
2. 双击"添加新块"
3. 选择块类型（OB/FB/FC/DB）
4. 选择编程语言（LAD/FBD/SCL/STL/GRAPH）
5. 设置块名称和编号
6. 编写程序逻辑

编程语言选择：
- LAD（梯形图）：离散逻辑控制，电气工程师易理解
- FBD（功能块图）：逻辑运算和数据处理
- SCL（结构化文本）：复杂算法、数据处理、循环运算
- STL（语句表）：仅 S7-300/400/1500 支持
- GRAPH（顺控图）：步进式顺序控制

========================================
第四部分：编译和下载
========================================

编译：
1. 项目树右键 PLC 站点 → "编译"
2. 选择"软件（仅修改的块）"或"软件（全部重建）"
3. 编译结果在信息窗口显示

下载到设备：
1. 确保 PLC 通过以太网连接
2. 点击"下载到设备"
3. 选择接口类型（PN/IE）和接口（网卡）
4. 点击"开始搜索"找到目标设备
5. 选择目标设备后点击"下载"

运行时下载：
- S7-1200 支持下载但不重新初始化
- 不会对控制过程造成负面影响
- 需要预先设置块的预留存储器

========================================
第五部分：在线诊断和监控
========================================

建立在线连接：
1. 项目树选择 PLC 设备
2. 点击"转至在线"（Go Online）
3. 选择通信接口并搜索目标设备

在线诊断功能：
- 查看块的运行状态（监控值）
- 查看 CPU 运行模式（RUN/STOP）
- 诊断缓冲区查看系统事件
- 模块诊断查看硬件状态

监控表（Watch Table）：
- 创建监控表监控/修改变量值
- 支持强制变量（Force）
- 支持修改变量值（Modify）

上载程序：
- "作为新站上传"：获取完整站点数据（硬件+软件）
- "从设备上传"：仅上传程序块
- TIA Portal 只能上传相同版本创建的程序

========================================
第六部分：IEC 61131-3 标准
========================================

五种编程语言：
1. LD（梯形图）：图形语言，源于继电器逻辑
2. FBD（功能块图）：图形语言，信号流导向
3. ST/SCL（结构化文本）：文本语言，类 Pascal
4. IL/STL（指令表）：文本语言，类汇编（2025版已废弃）
5. SFC/GRAPH（顺序功能图）：步进和转换控制

基本数据类型：
- BOOL（1 bit）：TRUE/FALSE
- BYTE（8 bit）、WORD（16 bit）、DWORD（32 bit）
- SINT（8 bit）、INT（16 bit）、DINT（32 bit）、LINT（64 bit）
- USINT、UINT、UDINT、ULINT（无符号）
- REAL（32 bit 浮点）、LREAL（64 bit 双精度）
- TIME、DATE、TOD、DT（时间类型）
- STRING（最长 254 字符）、CHAR（单字符）

复合数据类型：
- ARRAY：数组
- STRUCT：结构体
- PLC 数据类型（UDT）：用户自定义类型（推荐优先使用）

程序组织单元（POU）：
- PROGRAM → OB（组织块）
- FUNCTION_BLOCK → FB（功能块，有实例数据）
- FUNCTION → FC（函数，无实例数据）

变量声明段：
- VAR_INPUT：输入参数
- VAR_OUTPUT：输出参数
- VAR_IN_OUT：输入输出参数
- VAR：局部变量
- VAR_STAT：静态变量
- VAR_TEMP：临时变量

========================================
第七部分：命名规范
========================================

总体原则：
- 使用唯一且一致的英文标识符
- 块名使用 PascalCase（如 MotorControl）
- 变量使用 camelCase（如 motorSpeed）
- 常量使用全大写 SNAKE_CASE（如 MAX_SPEED）

变量前缀约定：
- pb：Push Button 按钮（如 pbStartMotor）
- sb：Switch Button 旋转开关（如 sbAutoMan）
- ls：Limit Switch 限位开关（如 lsCylinderOut）
- ton：定时器（如 tonDelayStart）
- ctu：计数器（如 ctuPartCount）
- has/is：布尔状态（如 hasDone, isRunning）

数据类型前缀（可选）：
- b：Bool（如 bIsRunning）
- i：Int（如 iCounter）
- r：Real（如 rTemperature）
- s：String（如 sDeviceName）
- dt：Date_And_Time（如 dtStartTime）
- a：Array（如 aMotorList）

========================================
第八部分：程序结构设计
========================================

推荐架构规则：
- 使用适当的编程语言（逻辑用 LAD/FBD，算法用 SCL，顺控用 GRAPH）
- 使用 PLC 数据类型（UDT）而非 STRUCT
- 只通过形参（接口）交换数据，不用全局变量直接访问
- 仅从块内部访问静态变量
- 输出参数只写一次

程序分层结构建议：
OB1 (主循环)
  ├── FB_SystemManager（系统管理）
  │     ├── FB_ModeControl（模式控制：自动/手动）
  │     └── FB_AlarmHandler（报警处理）
  ├── FB_Station10（工位10）
  │     ├── FB_MotorControl（电机控制）
  │     └── FB_ValveControl（阀门控制）
  └── FC_Communication（通信处理）

块设计原则：
- 每个 FB 完成单一明确功能
- FB 通过接口与外界交互
- 避免在 FB 内部直接读写全局 DB 或 I/O 地址
- 使用多实例减少数据块数量

========================================
第九部分：安全编程原则
========================================

通用安全编程规则：
- 每个 OB 周期中必须对所有输出赋值
- FOR/WHILE 必须有明确退出条件
- 设置合理的循环监控时间（看门狗）
- 除法运算前检查除数是否为零
- 数组访问前检查索引范围
- 设置通信超时处理逻辑
- 关键数据存入保持性存储区
- 手动/自动模式切换时安全处理输出

控制流规则：
- 用 CASE 代替 ELSIF 分支
- CASE 指令中必须创建 ELSE 分支
- 避免使用跳转（GOTO）和标签

注释规范：
- 块注释：描述整个块的功能、作者、版本
- 网络标题注释：描述该网络段的功能
- 行内注释：代码行级别说明
- 注释应写出意图（Why），而非解释语句做了什么（What）
- SCL 用 // 行注释和 (* *) 块注释
