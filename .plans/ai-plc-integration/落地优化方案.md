> 编写角色：Architect（系统架构设计）
> 依据：参考项目 `软件/` 目录代码行为分析 + 本项目 `orchestrator/` `mcp-servers/tia-mcp/` 现状审查 + `Siemens_SCL_外部源编程规范.md` V21 实测规范 + `TIAPortalOpennesszhCN.pdf` 官方文档
> 目标：从"617 测试通过 / Phases 1-5 完成 / 队列 IDLE"推进到"用户说一段需求 → AI 生成正确 SCL → 自动导入 TIA → 编译通过 → 下载到 PLCSIM → snap7 读到变量翻转"的真正可落地闭环

## 0. 当前关键缺陷（审查结论）

### 0.1 参考资料揭示的关键差距

参考项目 `软件/plc_-ai_-assist-main/` 是一个**已经跑通**的 C# WinForms 桌面应用，它的核心价值在于：

1. **TIA Portal Openness 直接调用** — `Program.cs` 演示了程序集解析（`AppDomain.CurrentDomain.AssemblyResolve`），`Form1.cs` 演示了完整对象树导航（`TiaPortal → Projects → Devices → DeviceItem → SoftwareContainer → PlcSoftware → ExternalSourceGroup`）
2. **AI → SCL → TIA 导入闭环** — 该项目的 `button3_Click` 演示了 `CreateFromFile → GenerateBlocksFromSource` 完整流程，并有多达 13 个实际生成的 SCL 文件（`AI生成块_2026*.scl`）作为证据
3. **SCL 外部源规范** — `Siemens_SCL_外部源编程规范.md` 提供了 TIA V21 实测的格式铁律，可直接转化为 AI 提示词约束

### 0.2 本项目缺陷清单

| 编号 | 位置 | 缺陷 | 影响 |
|------|------|------|------|
| D-01 | `tia-mcp/server.py:117-139` `_gen_scl_via_deepseek` | AI 提示词未注入 V21 SCL 外部源规范（无 `#` 前缀强约束、无 `String[n]` 禁令、无 `MB_CLIENT` 不可走外部源等关键铁律） | AI 生成 SCL 在 V21 编译失败率极高 |
| D-02 | `TiaWorker/Program.cs:283` `ImportScl` | 直接 `CreateFromFile`，未先删除同名外部源 | 重导同块报 `The name is not unique`，无法迭代修改 |
| D-03 | `tia-mcp/server.py:218` | 写 `.scl` 文件时未显式校验首字节非 `EF BB BF` (BOM) | 偶发 BOM 导致 `行 0 设定值 "" 无效` |
| D-04 | `orchestrator/workflows/tia_full_pipeline.py` | 6 步流水线无"编译失败 → 错误明细回传 AI → 重试"循环 | 一次编译失败 = 整条流水线死亡，不修复不重试 |
| D-05 | TiaWorker 命令表 | 无"先删外部源再导入"专用命令 | 必须手写两步，容易漏删 |
| D-06 | 流水线步骤顺序 | 未实现 `UDT → 变量表 → 全局 DB → FC/FB/OB → 实例 DB → 编译` 依赖顺序 | 多块导入时下游块引用上游 UDT/DB 会失败 |
| D-07 | `plc_download_project` | 下载到 PLCSIM Advanced 的端到端实测无验证记录 | 代码存在 ≠ 能真下载 |
| D-08 | `_gen_scl_via_deepseek` 返回解析 | `json.loads(content.strip())` 无 fallback | AI 偶发非纯 JSON 输出时直接抛异常 |
| D-09 | `tia_full_pipeline.py:121` | `generate_scl_code` 返回 `scl_code` 字符串但步骤 3→4 传递的是 `scl_path`；数据契约不匹配 | **最严重隐性 bug — 整条流水线实际跑不通** |
| D-10 | 编译错误非结构化 | TiaWorker `compile` 返回 `errors=数量`，不返回错误明细行号/文本 | AI 重试无错误上下文，无法自动修复 |

## 1. 方案总览

### 1.1 设计原则

1. **务实优先于完善**：每个阶段只做让闭环跑通的事，不做边际功能
2. **真实环境验证优先于单元测试**：成功标准是"在 TIA V21 + PLCSIM Advanced 实测跑通"，不是新增测试数量
3. **规范即契约**：`Siemens_SCL_外部源编程规范.md` 是 AI 提示词与导入流水线的共同单源真理
4. **错误可回溯**：编译错误必须能反向喂回 AI 重试，不是一次性失败
5. **不修改参考资料**：`软件/` 下的 C# 项目作为只读对照，不在那里改动一行代码

### 1.2 阶段划分

```
Phase L1 (1 周) ── 闭环打通：真实环境跑通最小 vertical slice
    ↓
Phase L2 (1 周) ── 规范即契约：SCL 生成质量从"偶尔能编"到"大概率一次过"
    ↓
Phase L3 (1 周) ── 迭代闭环：编译错误回传 AI 自动重试 + 多块依赖顺序
    ↓
Phase L4 (3-5 天) ── 一键启动 + Demo 脚本：可演示可分发
```

### 1.3 阶段成功标准

| 阶段 | 唯一成功标准 | 验证方式 |
|------|-------------|---------|
| L1 | 在真实 TIA V21 + PLCSIM Advanced 上：输入"电机启停带急停"→ AI 生成 SCL → 自动导入 → 编译 0 错误 → 下载到 PLCSIM → snap7 读到 `MotorRun` 位翻转 | 人工跑一次 + 终端日志存档到 `docs/verification/` |
| L2 | 连续 10 个不同需求（电机/PID/传送带/计数器/边沿/定时器/通信/CASE/FOR/REPEAT）首次编译通过率 ≥ 8/10 | 跑 10 个 prompt 固定集，统计首次通过率 |
| L3 | 故意让 AI 生成含 `String[32]` 错误的 SCL → 系统自动捕获 → 回传 AI 修正 → 二次编译通过 | 回归测试嵌入已知 bug 场景 |
| L4 | 新机器上 `.\start.bat` 一键启动 5 个服务 + 浏览器打开 → 5 分钟内跑完 L1 demo | 干净 Windows 11 + TIA V21 环境复现 |

## 6. 优先级排序

### 6.1 按"最快见效果"排序

| 排序 | 任务 | 工期 | 理由 |
|------|------|------|------|
| 1 | **L1-T1** | 0.5 天 | 修 D-09 数据契约 bug，最短路径让流水线有机会跑通 |

**先做 L1-T1 + L1-T2 + L1-T3（2 天）→ 跑一次 L1-T5（1 天）**：

如果跑通了：恭喜，最小闭环已通，继续 L2 提升质量。
