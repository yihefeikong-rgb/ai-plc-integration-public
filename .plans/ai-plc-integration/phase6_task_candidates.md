### C-14：cc-haha 受控 WS 任务投递 MVP

| 字段 | 内容 |
|------|------|
| **目标** | REST 建会话 + WebSocket 投递任务 + 处理权限请求 + 回填结果 + 停在 NEED_CODEX_REVIEW |
| **影响范围** | `bridge/` 新增 WS 适配层模块（Python WebSocket 客户端） |
| **前置条件** | C-13 确认 sidecar 端口可用 |
| **风险** | 低 — 纯 WS 协议通道，不越过 SafetyGate，第一阶段权限策略保守（自动拒写入类工具） |
| **预计工作量** | 中（1-2 天） |
| **执行链** | REST `POST /api/sessions` 建会话 → WS `/ws/{sessionId}` 发 `user_message` → WS 收 `permission_request` → 响应 `permission_response` → WS 收 `message_complete` → 回填 bridge 文件 |
| **边界** | 自动：发现端口→建会话→WS 投递→处理权限→回填→切状态；不自动：review/git/下一轮/重试；⛔ 不假设固定端口 |

## 三、任务优先级建议

```
第一优先（低风险，高价值）:
  C-01  前端测试初始化      → 填补最大测试缺口
  C-04  测试套件索引文档    → 降低新成员上手成本

第二优先（低风险，渐进优化）:
  C-03  归档脚本审查        → 清理技术债务
  C-06  Bridge v2 拆分      → 协作层基础设施
  C-13  sidecar 端口发现+探测  → cc-haha 自动化前置验证（不假设固定端口）
  C-14  受控 WS 任务投递 MVP   → REST建会话→WS投递→回填→停在Review

独立调查:
  C-02  根目录 data/ 核查   → 先核查再决定是否清理

第三优先（需人工审批）:
  C-08  真实环境冒烟        → 验证全链路可用性（前提条件满足后可插入第一优先）
  C-07  TiaWorker 拆分      → 改善核心模块可维护性
  C-09  生产环境硬化        → Pipeline 稳定化
  C-10  Factory I/O 集成    → 可视化验证

独立轨道（独立于主任务队列）:
  C-11  RBAC 安全网关        → 部署前置条件
  C-12  S7 写入安全加固      → 持续安全优化
```
